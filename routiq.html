The starting point

It started with
a simple question.

How could someone keep daily habits manageable and understand their progress? The brief proposed an AI-powered mobile product. I separated that ambition into clear requirements, open questions, a focused first release and a later evidence-bounded product iteration.

The opportunity

The brief proposed easier daily recording and clearer progress. I treated that as a hypothesis to explore, with the lack of participant evidence kept visible.

The working release

The first increment delivered add, track and prepared-answer guidance. The latest iteration adds optional rewards, foreground reminders, Settings, durable same-browser data, richer habit cues and a floating AI Assist.

The assignment

The project now has a public Angular frontend on Vercel, connected to a prepared-FAQ Python API on Render, with bounded automated and browser verification across phone, tablet and desktop layouts.

Implemented ≠ validated outcomeThe current web application implements the documented iteration. Native apps, production accounts, background push, live personalized AI, cross-device sync and participant-validated behavior change remain outside this release.

Published research

Consistency is more than a counter.

Lally and colleagues studied contextual repetition over 12 weeks with 96 volunteers. Automaticity trajectories varied; the abstract reports that one missed opportunity did not materially affect formation.

Question for Routiq: can progress feedback explain recorded activity without promising a universal habit-formation deadline or treating one miss as total loss?

Lally et al. · publisher abstract
Abstract-level review; self-report/modeling, narrower model-fit coverage. This does not settle streak calculations or repeated-miss behavior.

Published research

Reminders carry tradeoffs.

A 30-volunteer notification study reported less distraction and greater productivity under suppression, alongside anxiety about responsiveness for some participants. Others did not share that anxiety.

Question for Routiq: what reminder timing and control help in the actual routine context? Neither more alerts nor blanket suppression is established as the right policy.

Pielot & Rello · author paper
Short, dated, self-reported, white-collar sample; all-device notifications, not a habit-reminder trial.

Product documentation

Meaning matters more than novelty.

Productive documents skip-inclusive totals, Loop describes a graded habit score, and Habitify already documents habit-aware AI. Similar labels can represent different rules.

Question for Routiq: are progress explanations and optional habit experiments understandable and useful compared with existing alternatives?

Documentation establishes stated capabilities; it does not measure comprehension, effectiveness or market-wide uniqueness. See the comparison below.

Competitors made the choices clearer.

Approved with limits

The six-product comparison showed several ways to frame habits: conversational guidance, calendar totals, game rewards, streaks and graded scores. I used official documentation to understand those differences, rather than ranking products by untested usability or effectiveness. No additional product-owner answer is required for this approved v1.0 review; hands-on audits, pricing parity and measured accessibility remain optional future research.

Provisional hypothesis

Keep daily intentions manageable.

A person may struggle to keep intended recurring activities and recorded completion manageable through the day.

Design hypothesis: connect habit configuration and daily recording. The current build explores this through a small habit editor and Today checklist.

Provisional hypothesis

Understand progress after interruptions.

A person may struggle to interpret what recorded history means, especially after missed or skipped opportunities.

Design hypothesis: use transparent metrics. The build shows completion counts and recorded activity; streak calculations are outside the release.

Agree metric rules, then assess actual interpretations and errors.
Provisional hypothesis

Judge a useful next step.

A person may lack enough understandable context to decide which routine adjustment is relevant and worth trying.

Design hypothesis: offer contextual guidance as optional experiments. The assignment implements prepared FAQ replies and local Today summaries.

Investigate usefulness, permitted context and overtrust; the deployed FAQ is not personalized live AI.

Make the next question part of AI Assist

The first prepared-chat release always showed the same four sample questions. I refined the interaction so the next choices relate to what the user has just asked, whether they select a suggestion or type a question.

The backend returns four curated follow-ups with each reply. The frontend keeps the latest topic for short follow-ups, avoids recent repeats and excludes the question just asked.

  • AI Assist begins with four starter questions.
  • Each successful reply replaces them with four related choices.
  • Changing from reading to workout ideas, rewards, reminders or Today changes the suggested direction.
  • A failed request keeps the previous choices and typed question available for retry.
  • Reloading clears page-session messages; the visible New chat control was removed in the annotation pass.

The released catalogue covers 255 existing FAQ questions plus 15 curated feature questions. No model call or account history is added.

The latest product iteration

I expanded the release
without hiding its limits.

After the first public assignment worked, I planned and implemented a bounded application iteration. It adds motivation, reminders, personalization and more contextual assistance while preserving a local-first data model and prepared-answer AI boundary.

Optional rewards

Eligible daily completions earn 10 points. Milestones appear at 1, 5 and 20 completions; undo recalculates the total. Rewards can be turned off without deleting activity.

Foreground reminders

Per-habit times, quiet hours, 10-minute snooze, daily dismissal and completed-habit suppression work while Routiq is open. Closed or suspended tabs cannot promise delivery.

General settings

Display name, local profile-photo upload/removal, theme, reduced motion, celebrations, rewards, reminders, version and saved timezone are managed on the device.

Floating AI Assist

Coach became AI Assist. It opens as a floating tablet/desktop window and a full-screen mobile layer that hides bottom navigation, while retaining four contextual follow-up questions.

Behavior-support tools

  • Optional reason for each habit.
  • A small first action and routine cue.
  • Reflection prompts in Progress.
  • Progress feedback and optional achievements.

These mechanisms support planning and reflection; they are not proof of lasting behavior change.

Annotation-led refinements

  • Balanced select padding and inset arrows.
  • Top-aligned cards without generic task icons.
  • Single-line truncated habit details.
  • Icon-only mobile actions with accessible names.
  • Full-width mobile Save preferences.
  • New chat removed; reload guidance retained.

What the process taught me

What changed
along the way.

The project started with a broad mobile and AI ambition, reached a focused working assignment, and then moved through a controlled application iteration. Each step kept implementation evidence separate from user validation.

Separate the ambition from each increment.

The original mobile/AI concept was wider than the first deliverable. A focused add/track/chat release established the foundation; the next bounded increment added rewards, reminders, settings and floating assistance without pretending the roadmap was finished.

Local-first features need explicit boundaries.

Durable browser storage, profile photos, reminders and rewards can work without an account, but same-device data is not a backup and foreground reminders cannot promise delivery from a closed tab.

Iteration includes correction and verification.

Browser annotations changed card alignment, truncation, mobile actions, select spacing and profile controls. Automated checks and responsive browser review established bounded behavior; participant value and accessibility still need evidence.
